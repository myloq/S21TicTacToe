# S21TicTacToe

Учебный проект, выполняемый в рамках образовательного проекта от Сбер «Школа 21». Представляет собой последовательность связанных заданий, развивающих одно и то же серверное приложение: от минимального веб-API до полноценного бэкенда с базой данных, авторизацией и сетевой игрой.

## Project 03. Серверная часть на ASP.NET

### Описание

Реализация серверной части игры «Крестики-нолики» в виде веб-приложения на ASP.NET с разделением на независимые модули. Хранение данных осуществляется в оперативной памяти.

### Архитектура

Проект реализован с применением принципов чистой архитектуры (Clean Architecture). Решение разделено на независимые проекты, что обеспечивает слабую связанность и упрощает тестирование:

- `TicTacToe.Domain` — ядро приложения (модели, интерфейсы, бизнес-логика, алгоритм Минимакс).
- `TicTacToe.Datasource` — слой доступа к данным (EF Core, контекст базы данных, репозитории, миграции).
- `TicTacToe.DI` — конфигурация графа зависимостей (Dependency Injection).
- `TicTacToe.Web` — уровень представления (ASP.NET Core Web API, контроллеры, обработчики исключений, кастомная аутентификация).

### Технологический стек

- **Язык и платформа:** C#, .NET 
- **Веб-фреймворк:** ASP.NET Core Web API
- **ORM:** Entity Framework Core
- **СУБД:** PostgreSQL
- **Контейнеризация:** Docker (для локального развертывания БД)
- **Тестирование:** Postman (автоматизированные коллекции тестов)


### Реализованная функциональность

- Модель игрового поля в виде целочисленной матрицы и модель текущей игры с UUID.
- Сервис с методами:
  - вычисление следующего хода компьютера алгоритмом «Минимакс»;
  - валидация игрового поля (проверка, что ранее сделанные ходы не изменены);
  - проверка окончания игры.
- Мапперы `domain ↔ datasource`.
- Репозиторий с методами сохранения и получения текущей игры.
- Контроллер с методом `POST /game/{UUID}`: принимает игру с ходом пользователя, возвращает игру с ответным ходом компьютера. При некорректном поле возвращается ошибка с описанием.
- Поддержка нескольких одновременных игр.
- Граф зависимостей: хранилище - singleton, репозиторий и сервис - через DI.

## Project Backend 04. База данных, авторизация, игра между игроками

### Описание

Развитие проекта предыдущей недели: отказ от хранилища в памяти в пользу PostgreSQL, добавление пользователей и авторизации, а также переход от игры с компьютером к игре между двумя игроками.

### Технологии

- C#, .NET
- ASP.NET (контроллеры, атрибуты `[Authorize]` и `[AllowAnonymous]`, коды состояния, включая 401)
- PostgreSQL и драйвер/ORM для работы с ней
- HTTP Basic Authentication (заголовок `Authorization`, `base64(login:password)`)
- Внедрение зависимостей
- `System.Guid` для идентификации пользователей и игр

### Реализованная функциональность

**База данных**
- Подключение к PostgreSQL.
- Класс-хранилище в оперативной памяти удалён.
- Модели, сохраняемые в БД, размечены соответствующими аннотациями.

**Пользователи и авторизация**
- Модель пользователя: UUID, логин, пароль. Поддержка пользователей реализована на всех слоях.
- Модель `SignUpRequest` (логин, пароль).
- Сервис авторизации на основе `UserService`:
  - регистрация пользователя;
  - авторизация по заголовку `Authorization` со схемой Basic, возвращает UUID пользователя.
- Контроллер авторизации с endpoint'ами регистрации и авторизации.
- `UserAuthenticator` на основе атрибута `[Authorize]`: валидирует учётные данные, при ошибке возвращает код 401 без выполнения запроса.
- Endpoint'ы регистрации и авторизации доступны без авторизации (`[AllowAnonymous]`), все остальные — требуют её.

**Игровая логика**
- Состояния текущей игры: ожидание игроков, ход игрока с UUID, ничья, победа игрока с UUID.
- Информация о символах (значках), которыми ходят игроки, хранится в текущей игре.
- Определение окончания игры переработано с использованием состояний.
- Endpoint'ы:
  - создание новой игры с пользователем или компьютером;
  - получение списка доступных текущих игр;
  - присоединение пользователя к игре;
  - обновление текущей игры (с учётом режима игры);
  - получение текущей игры;
  - получение информации о пользователе по UUID.

## Запуск проекта

### 1. Подготовка базы данных
Убедитесь, что Docker запущен. Выполните команду для развертывания контейнера PostgreSQL:
```bash
docker run --name pg_dev -e POSTGRES_USER=user -e POSTGRES_PASSWORD=user -e POSTGRES_DB=tictac -p 5432:5432 -d postgres:16
```

### 2. Применение миграций
В корневой папке решения примените миграции для создания структуры таблиц в базе данных:
```bash
dotnet ef database update --project TicTacToe.Datasource --startup-project TicTacToe.Web
```

### 3. Запуск приложения
Запустите сервер:
```bash
dotnet run --project TicTacToe.Web
```
По умолчанию API будет доступно по адресу: `http://localhost:5290`.
